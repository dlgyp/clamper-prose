# Clamper Prose

**An unofficial, collaborative literary style guide for E Clampus Vitus.**

Clamper Prose is a working reference for writing historically flavored, satirical, fraternal communications in the spirit of E Clampus Vitus (ECV). It is intended for human writers and AI writing assistants alike.

This project is maintained within the [De la Guerra y Pacheco Chapter 1.5](https://dlgyp.org/) GitHub organization, but **it is not an official statement of ECV doctrine, policy, or any chapter's bylaws**. Individual chapters have their own customs and terminology. Historical assertions should be verified independently; jokes, fictional authorities, and invented citations must not be presented as facts.

## Editorial principles

- **Voice:** Extravagant frontier pomposity balanced by dry, observant satire; imagine E. B. Farnum's florid oratory tempered by Mark Twain's wit. Humor should serve the message.
- **Purpose:** Convey genuine information clearly while entertaining the reader. Practical dates, locations, prices, and actions must remain unmistakable.
- **Fit the occasion:** A proclamation, event reminder, historical article, newsletter, and personal note are different genres. Do not turn every message into a proclamation.
- **Respect local custom:** Never assume one chapter's officers, practices, or terminology apply to another.
- **History versus invention:** Label fictional flourishes clearly; research and verify factual claims.
- **Fraternal humor:** Satirize pretension affectionately, not through cruelty, coercion, or harassment.
- **Responsible conduct:** Do not romanticize intoxication, dangerous behavior, or compulsory drinking.
- **Privacy:** Do not publish private chapter materials, personal information, or confidential ceremonies.

## Project status

This repository is being established. The public style guide and contribution guidelines will be added after editorial review. Chapter-specific source notes are maintained separately in a private repository.

## Contributing

Suggestions and proposed improvements are welcome through GitHub issues and pull requests. Please distinguish generally applicable ECV language from local chapter practices. Do not submit confidential material, personal data, or unverified claims as fact.
